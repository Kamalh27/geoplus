# CLAUDE.md — geoplus

Standalone Next.js geospatial dashboard editor, extracted from the main `website` app.

## Commands

```bash
npm install
npm run dev       # :3001
npm run build
npm run lint
npm run test:geoplus
npm run sync:assets   # copies duckdb-wasm + maplibre worker into public/ (also runs on postinstall/predev/prebuild)
```

maplibre-gl 6 is ESM-only and loads its worker from `public/vendor/maplibre/` (gitignored, generated by
`scripts/sync-maplibre-worker.mjs`); `lib/maps/maplibreWorker.ts` calls `setWorkerUrl` and must be imported
before any map is created (it is, from `components/geoplus/map/use-map-init.ts`). deck.gl uses
`@deck.gl/maplibre` (`MapLibreOverlay`), not `@deck.gl/mapbox`.

## Architecture

### App Structure

```
app/             Next.js app router pages
components/      geoplus* components, map controls, UI primitives
lib/
  geoplus/
    dashboard-cache-storage.ts   OPFS cache helpers
types/
```

### OPFS Cache Strategy

Editors use Origin Private File System (OPFS) as a local working store. The **backend is always the source of truth**.

| Actor | OPFS role |
|-------|-----------|
| Editor | Read/write drafts, autosave recovery, repeat access to large uploads |
| Viewer | Read-only cache for repeat loads; falls back to backend if stale/missing |

Rules to enforce:
- A successful backend Save must refresh the OPFS dashboard cache.
- Shared dashboards must never depend on another user's OPFS (OPFS is private per browser profile).
- If OPFS data conflicts with backend data, backend wins.

Cache helpers: `lib/geoplus/dashboard-cache-storage.ts`.

## Key Notes

- This app contains only GeoPlus-focused code. The original `website` app is left untouched for incremental migration.
- No backend in this directory — it talks to `platform/core/backend` APIs.
- `NEXT_PUBLIC_CORE_BACKEND_URL` controls the backend base URL (dev default `http://localhost:8010`; ports 3000/8000/8001 belong to another project).

## Sign-in (Spadace Account, plan P3-b3)

- GeoPlus is its own Account web client (`geoplus-web-dev`, return address `http://localhost:3001/auth/callback`).
  Authorisation code + PKCE; logic and tests in `lib/server/account-session.ts` (server-only, Node `crypto` + `fetch`, no
  dependency). Routes: `GET /api/geoplus/auth/login?next=`, `GET /auth/callback`, `POST /api/geoplus/auth/logout`
  (same-origin only, answers `{redirect_to}`), pages `/auth/signed-out`, `/auth/error`.
- Account tokens live only in the sealed (AES-256-GCM, `GEOPLUS_SESSION_KEY`) HttpOnly cookie `geoplus_session`
  (`__Host-` prefixed and `Secure` in production). Never expose tokens to client code or logs.
- Renewal: `ensureFreshSession` at 4/5 of the access token's life; the new refresh token is written to the response
  cookie before the access token is used. Concurrent refreshes are coalesced per process only (see the module comment).
- Settings: `.env.example` (`ACCOUNT_*`, `GEOPLUS_SESSION_KEY`). Local fake Account: core's `just fake-account`
  (port 8059, secret `fake-secret-geoplus-web-dev`).
